## Key Recent Facts
- **Visibility is not writability, and `settable_scopes` only answers the second** ([[h-config-audience-declared-on-key]], 2026-07-28). Four of `/config`'s five key-pickers filter on `settable_scopes` — which reads like a permission filter and isn't — and the fifth, `_KEYS_VIEW` (`extensions/config.py:25`), filters on nothing while `ConfigView` (`:245`) checks nothing. So `chardle_debug_board`, `chardle_epoch`, `chardle_abandon_hours`, `polling` are in every user's picker today, and deleting `/config global` closes neither the clutter nor the leak. Fix goes on the data: `audience: Literal["user","owner"]` on `ConfigKey`, every user-facing comprehension carries the predicate, default `"user"` so forgetting yields noise not a silent gate. One layer below the gate-on-the-service-not-the-command rule — that moved gates off the command onto the service, this moves them off the service onto the definition.
- **`/run` is one flat command, one free string, and a FOUR-layer gate** ([[h-owner-surface-is-run-terminal]], **built 2026-07-28**). Registration in `OWNER_GUILD_IDS` is the first layer and the cheapest — but it must be passed as a tuple, because `client.py:610-620` reads `guilds=None` as "fall back to `default_enabled_guilds`", and `Loader.command`'s second-order decorator drops `global_`, so register by function call. `AutocompleteContext` has no `user`; the invoker is `ctx.interaction.user.id`. Autocomplete callback returns `[]` for non-owners — *this* is the layer that closes the leak, and nothing fails without it; handler checks `owner_ids` — the only authority; `default_member_permissions` hides the row — visibility only, and guild admin ≠ bot owner. Verified in the pinned lightbulb: `commands.py:88` exposes it, `commands.py:190` **rejects it on subcommands**, so `/run` can never become a `Group`. Verb-first `shlex` grammar, flat dispatch, one small handler + one formatter per verb — never a generic dump, or [[w-sid-confined-to-sessions]] dies at the first `session inspect`. **No shell state**: slash commands are one-shot; "terminal" describes the box, not a REPL. Scope rule binds both ways — internals-only behind `/run`, and anything a user would want gets a real discoverable command instead.
- **Autocomplete is a hint, not a constraint** ([[d-autocomplete-is-a-hint]]) — free text is always submittable (`liveupdates.py:285` already says so), a chosen row replaces the **whole** option value so each suggestion must carry the rebuilt line, and the 100-char choice cap therefore lands on the *line*, not the token — which is what makes a long grammar silently uncompletable while still typeable. 25 rows, ~3 s, so the partial-line parser stays pure and DB-free. Replacement semantics are from docs, **not captured** — tracked in [[h-run-terminal-build-time]].
- **Every `type="int"` config key WAS persisted as a string — fixed 2026-07-28.** `set_value` (`settings/service.py:71`) writes `{"v": value}` verbatim and the old command layer validated only the tuple case, so `chardle_bpm_window`, `chardle_note_window` and `chardle_abandon_hours` returned `int` from the default path and `str` once anyone set them. Now `parse_value` (`settings/parse.py`) coerces on **both** write paths, and validates `type="timezone"` through `ZoneInfo` too — otherwise a typo'd zone reports "saved" while `parse_zone` silently falls back at read time. No rows needed migrating: the dev database held none.
- **"Unknown anywhere in the pool" is not the same rule as "constant across the pool"** (2026-07-28 fix, [[d-chardle-dead-clue-columns]]). `columns._informative` had both, and the extra clause deleted `charter` on **every** tier (41–42 Future/Present/Past charts carry no charter link, 11 Beyond, 8 Eternal) and `artist` on all but `byd` (one chart). Its docstring justified the clause as how err drops `level`/`rating` — **false**, err stores `-1` uniformly and the variance rule handles it alone. Knock-on: eligible fillers never exceeded the budget, so truncation never truncated and `rng.shuffle` was dead — **4 board shapes per tier**, not the "shape is itself a variable" the domain page promises. Now 20 per tier / 40 on extras / 7 columns always. Relaxing it needs the other half: drop a column the **answer** has no value for, or every row renders ⬛. Pinned by `tests/test_chardle_columns.py` against the live catalog. General shape: *a per-row unknown is a rendering concern (`UNKNOWN_CELL`), not a reason to delete the column for everyone.*
- **Chardle is BUILT** (2026-07-27) — emoji renderer, migration `a97f24335635`, `/chardle daily|play|guess|end|stats|help`. Reply path needs the **MESSAGE_CONTENT** intent (portal toggle). See [[chardle|Chardle]] + [[chardle-module|chardle (module)]]. **Three** modes (daily / free play / free play with filters) on **three tables with no mode column**: a mode is a shape of rows ([[h-chardle-puzzle-rows-not-modes]]). `puzzle_number IS NOT NULL` ⇒ daily; `channel_id` vs `discord_id` ⇒ free play vs daily. Clue columns are **frozen on the puzzle**, not rolled per session, which is what makes a shared daily possible at all — the prototype rolled them in `__init__`. Difficulty is revealed, not hidden. `chardle/` is a **pure catalog consumer**: it must not import `arcaea/` or `sessions/`, and it plays fine with lowiro unreachable.
- **The Chardle channel parents threads only; it never moves an inline board** (fix, 2026-07-27). Iteration 2 routed *both* legs of `/chardle play` there, so one live board per channel became one live **inline** board per **guild** — a board in the Chardle channel made every other channel answer "Busy". Now: `thread: none` posts where typed, anywhere; `thread: public|private` parents to the Chardle channel from any invocation channel and is **refused** when none is set; `/chardle daily`, which has no inline form, falls through to **DM** there. `transport.resolve_daily` takes `parent_channel_id: int | None` and returns the DM **before** the reuse branch — otherwise it compares a thread's parent to `None`, fails, and reaches `create_thread(None, ...)`. `_parent_channel`'s "or the invoked channel" fallback is deleted, and that fallback *was* the bug. **A parent the player can't see counts as no parent** — thread access is inherited, so `can_view` (new in `utils/permissions.py`, VIEW_CHANNEL, only-False-rejects) gates it: `play thread:` refuses, `daily` takes the DM leg. Paired with `everyone_can_view` at **config** time, because the per-member gate only fires one player at a time — `/chardle channel` **warns** (never refuses) when @everyone can't see the channel being set, since "@everyone denied, Member allowed" is an ordinary server and the check can't tell whether that role covers everyone.
- **Race is gone; a board is owned by where it lives** ([[h-chardle-boards-are-channel-owned]], 2026-07-27). Every non-daily board is **channel-owned**, only dailies are user-owned. Solo play comes from *location*, not a permission check — a DM holds one human, a thread has its own channel id. Trigger was the owner's observation that **the two boards look identical to a player**: same art, same flow, differing only by whether your guess is silently rejected. Three findings got it there: race's spec contradicted itself ("free" attempts *and* "one budget"); racing the daily was a **stats loophole**, not just a spoiler, because a channel session's `discord_id IS NULL` slips `UNIQUE (puzzle_id, discord_id)`; and unlocked free play collapses onto race anyway, since lookup must move to the channel. `/chardle race` and `/chardle custom` both dissolve into `/chardle play`; custom is `play` with filter options.
- **`user-owned ⇔ daily` is enforced by a composite FK**, not by service code. `is_daily` is a generated column on `chardle_puzzles` with `UNIQUE (id, is_daily)`, denormalised onto `chardle_sessions` and tied back through `FOREIGN KEY (puzzle_id, is_daily)`, so `CHECK ((discord_id IS NOT NULL) = is_daily AND (channel_id IS NOT NULL) = NOT is_daily)` can see across both tables — a plain CHECK cannot. That one constraint replaces the old xor **and** closes the daily-as-race loophole. Plus `UNIQUE (channel_id) WHERE state = 'playing'` — one live board per channel, which in a DM is one per user. A *lost* board frees the slot for free; an **abandoned** one needs `/chardle play end` + an inactivity sweep (whether that reuses `expires_at` is unsettled). `filters ⇒ stats-ineligible` turns out **redundant** — real eligibility is `puzzle_number IS NOT NULL`.
- **Dailies are private and live in a private thread** (2026-07-27, [[h-chardle-boards-are-channel-owned]] §A daily is private) — guild **with a Chardle channel set** → private thread the bot opens under it and adds the player to; DM, or a guild that has set no channel, → the DM channel (threads are refused, never opened off the invoking channel — see the 2026-07-27 fix below), **ephemeral only as a last resort** because an interaction token dies after 15 min and an ephemeral board therefore cannot be edited across a daily's life. Thread is **reused per (guild, player)**, not per puzzle. Forces a schema split: `channel_id` = **ownership** (free play only), new `board_channel_id` = **transport**, `CHECK (channel_id IS NULL OR channel_id = board_channel_id)`. `message_id` becomes NOT NULL. `MANAGE_THREADS` can join a private thread, so the reply path *also* checks the guesser **is** `session.discord_id` — location narrows the audience, the check enforces it. hikari support verified in-env (`create_thread`, `add_thread_member`, `GUILD_PRIVATE_THREAD`).
- **The answer outranks the delisted cloak** ([[h-chardle-closest-match-always-costs]] §Rule 0) — `SearchService._chart_visible` gates delisted **and** err on the same `include_hidden` flag, so a song delisted *after* its puzzle was created would be cloaked out of its own game and strand the board. Naming the answer wins regardless of visibility; every other delisted song stays an invalid, free guess. **Exact tier only** — fuzzy would hand the win to a near-miss. Also: candidates are filtered to the puzzle's difficulty **before** the resolution rules run, or rules 3 and 4 disagree about the same guess (charge vs refund).
- **Clue column order is a canonical constant**, membership is what varies — `jacket · title · artist · level|rating · pack|version · charter · side · class · bpm · note`, cap **7 counting `title`**. Confirmed against the prototype, which appended in fixed order and rolled only membership; its cap could leak to 8 via the `level`/`rating` branch. Deterministic order is what makes the emoji share grid mean the same thing every day.
- **The daily's timezone paradox is resolved by numbering, not dating** ([[h-chardle-puzzle-number-not-date]]). Per-guild rollover and global per-user streaks contradict as usually stated. Fix: one global puzzle sequence, guild timezone moves only the *unlock instant*, and **streak = longest run of consecutive `puzzle_number`** — never calendar days. `guild_id` on a session is attribution only; computing any stat from it reintroduces per-guild streaks. Daily `max_attempts` pinned at **6** because a guess-distribution histogram over a varying denominator is incoherent — one-way door. **Rollover is local 00:00 + 4 h, default zone GMT+7** — clear of DST, which transitions 02:00–03:00 local. Number is **calendar-derived, never a counter**: `number = ((local − 4h).date() − EPOCH_DATE).days + 1`, so a day nobody plays leaves a **gap**, and a counter closing that gap would report streaks that never happened. Lazy creation races resolve by re-reading the winner's row, not erroring.
- **Chardle guesses never open a picker** ([[h-chardle-closest-match-always-costs]]): unique → resolve; ambiguous with the answer among candidates → that one, you win; ambiguous otherwise → closest match, **attempt consumed**; unresolvable → free. Showing a picker only when nothing matches would leak "no Quon is the answer" for zero attempts. The cost is that **rows must carry a pack/artist tiebreak label** when the resolved song's `name_en` is non-unique, or the board misreports what it measured.
- **Chardle's pools are three families, sized from the live catalog** (2026-07-27): base (`pst`/`prs`/`ftr`, 540 each), **extras** = `byd` 63 + `etr` 103 + `byd_2` 1 = **167 charts over 166 songs**, and **err = 7**. The extras tier reveals only **"Extra"**, never the class ([[h-chardle-extra-pool-hides-class]]) — viable because **165 of 166 songs carry exactly one extra**, so "the song's extra" is a well-defined guess target; Last is the sole exception. Hidden class becomes its own `class` clue column, valid on extras puzzles only. **`byd_2` is NOT a class** (owner, 2026-07-27) — it is the mechanism letting one song hold two charts *in* a class, and players have no concept of it; they know Last has two Beyonds and that game and bot both handle it silently. So the tier holds **two** visible classes, the `class` column is **binary**, and Last's tiebreak (answer-preference, else first Beyond) is invisible from the player's seat.
- **All 7 err charts store `level = -1` AND `rating = -1`** — two clue columns dead 100% of the time, not merely weak. (Corrected 2026-07-28: the third, `bpm`, is **not** dead — only 2 of 7 set `bpm_base` on the chart row but all 7 inherit their song's, and `ChartFacts.bpm` is the `effective()` value. The two that *are* also dead are `charter`, since all seven override charters to empty, and `side`, since all seven are Conflict. An err board runs 5 columns.) That number also retro-justifies the prototype's unexplained `max_attempts = 3`: with 7 answers, 6 attempts is unlosable. err is a **dated event** ([[h-chardle-err-is-an-event]]) — guaranteed April 1, 25% that week, **0.3%** otherwise, never a random daily. An **attempted** err daily counts as solved for the streak win or lost, and is excluded from the guess histogram — an April-1-only exception; **skipping April 1 still breaks the streak**. Attempts are **derived, not hardcoded**: `min(max(⌊N/2⌋,1),6)`, N = err charts counted with `include_hidden=True` (they store `rating = -1`, which is also the delisted predicate, so the ordinary path counts 0), frozen at puzzle creation → **3** today. err charts are unguessable in every other mode via `include_hidden=False`, passed straight through to `SearchService` — chardle adds no cloaking of its own.
- **Delisted charts are in the catalog right now** — FTR `min_cc = -88`, PRS `-60`, PST `-35`. Chardle's negative-CC exclusion is load-bearing, not theoretical.
- **Retyping an ambiguous name cycles to the next reading** ([[h-chardle-closest-match-always-costs]] §Cycling) — `quon` twice reaches both Quons, a third time is a free duplicate rejection. **Zero new state**: `UNIQUE (session_id, song_difficulty_id)` is both the dedupe rule and the cycling cursor, so the board *is* the pointer and interleaved guesses still advance. **Bounded to the exact-match tier, never the fuzzy tail** — unbounded it would resolve a repeated `tempestissimo` to some unrelated song and charge for it. Reply-path only; autocomplete already disambiguates.
- **Rendering is the one open Chardle question** ([[h-chardle-board-rendering]]) — deliberately deferred so rules could settle first. Note that the share string forces a text renderer to exist anyway, which makes "text grid" the incremental-cost-zero option. **The renderer choice changes display *rules*, not just looks**: a text board has no jacket, which promotes the pack/artist tiebreak label from conditional to mandatory.
- **The jacket is an identifier, not a clue — and it stays.** Early in the session it was written off as a dead column because `get_shadow` returned `None`; the owner corrected that (2026-07-27) — it exists to identify the row alongside the name, and "no feedback" is not "no information". The real defect is **cost**: identity does not need a full 220 px flex column. Cycling made it matter more than in 2024, since a board can now hold two rows both titled `Quon`. **Placement is being drafted by the owner in Figma**, not decided in prose — inset / gutter / dimmed background all still live. Pack-or-artist label renders **only when `name_en` is non-unique**.
- **The live-updates poster is BUILT** (2026-07-24) to [[live-updates|Live Updates (poster)]]'s design. `scores/poster.py` (queue → routing → per-destination dedupe + FIFO locks → send), `scores/filters.py` (triggers OR-ed `all`/`pb`/`bX`/`pm`/`fr`/`grade_up`, gates AND-ed `min_level` + guild floor, `PlayFacts` shared per play across linked users), `scores/suppression.py`. Migration `7ac31e9b0d54` adds the filter columns to `live_update_prefs`, the floor columns to `live_update_channels`, and flips `enabled`'s server default to false. Commands: `/liveupdates filters`, `/liveupdates floor`. Per-user columns, not `REGISTRY`; default `pb`; b30 feeds `bX` but the **aggregate is never printed**; posts carry the owner's Discord avatar + name via `set_author`, degrading to the Arcaea in-game name, never to `friend_code`.
- **`ingest` now returns row ids**, and `poller._store` sorts by `time_played` *before* ingesting — that ordering is what makes the live feed read in play order, since `ingest` preserves input order and hands ids straight to the poster's queue.
- **`play_scores` is a SAMPLE, not a log** — both read paths return only the single most recent play, so plays made between polls are never fetched and never can be. Every "PB" and every b30 figure is computed over *observed* plays. No user-facing copy may promise completeness. It also reframes the "posting everything would flood a channel" premise: the bounding unit is the **player**, not the poll key — one `/friend/me` returns a play per friend, so a bot key can yield many at once, but any one account surfaces ≤1 play per cycle (~40/hr at the 90 s default). A channel K users point at can still burst K posts in one cycle; that is what the stagger and the guild floor are for.
